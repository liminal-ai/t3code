For this probe, completed user, assistant, and command items carried the full normalized content needed for capture, including `payload.data.item.aggregatedOutput` for the 108,894-byte `seq 1 20000` output. Deltas are useful for live UI but are not required to reconstruct final content in this run. Evidence: `packages/lhc-host/test/fixtures/event-fidelity/codex/codex-normalized.jsonl` lines 7, 9, and 19; size summary in `codex-normalized-summary.json` lines 31-42.

Claude: do not rely on `item.completed` alone as a universal capture source. Assistant text is self-contained in `payload.detail`, but normal user prompts did not appear as `item.completed` user-message items; large command output is lossy in `payload.data.result.content`, `content.delta`, and inline `raw`. Patch `apps/server/src/provider/Layers/ClaudeAdapter.ts` in `handleUserMessage` where `toolData` is built: when `raw.payload.tool_use_result.persistedOutputPath`/`persistedOutputSize` is present, read or otherwise surface the full persisted output into a durable normalized field such as `payload.data.result.fullOutput` plus size/path metadata. Also patch Claude reasoning mapping if reasoning capture matters: this run's rollout has a `thinking` block, but the normalized stream emitted no reasoning item/delta. Evidence: `claude-normalized.jsonl` lines 12-14 and `claude-rollout-excerpt.jsonl` lines 8-10; sidecar proof in `claude-tool-result-sidecar-excerpt.txt` lines 1-41.

(Post-patch, this fork.) Both Claude gaps above are fixed in `apps/server/src/provider/Layers/ClaudeAdapter.ts` (slice 1.0): completed command items carry the sidecar contents in `payload.data.result.fullOutput` with `fullOutputPath`/`fullOutputSize` metadata, and thinking blocks emit normalized `reasoning` items with `reasoning_text` deltas. Post-patch fixtures live in `packages/lhc-host/test/fixtures/event-fidelity/claude/post-patch/`; see the amended rows below and the "Claude Post-Patch Re-Run" section.

## Method

I added scratch probe scripts under `packages/lhc-host/probes/`. They are outside `packages/lhc-host/src`, and `packages/lhc-host/tsconfig.json` includes only `src`, so they are not part of normal package typecheck/test globs.

Each provider ran in a fresh temp git repo with three turns: large command output (`seq 1 20000`), a small file edit, and an interrupted/failed slow-turn probe. Fixture files are trimmed under `packages/lhc-host/test/fixtures/event-fidelity/{claude,codex}/`; summaries preserve original byte counts and source line numbers.

### Claude Post-Patch Re-Run (Slice 1.0, this fork)

Date: 2026-07-07. After patching `ClaudeAdapter.ts`, the probe was re-run for Claude only (one session, two turns) with new flags:

```sh
node packages/lhc-host/probes/event-fidelity-probe.ts --provider claude --thinking --turns large-tool-output,reasoning --out-dir packages/lhc-host/test/fixtures/event-fidelity/claude/post-patch
```

`--thinking` selects `claude-haiku-4-5` with the `thinking` boolean option (mapped to `alwaysThinkingEnabled` by the adapter) and enables a `reasoning` turn ("think step by step about whether 91 is prime"); `--turns` filters turn labels. Fixtures were trimmed with the existing trimmer into `packages/lhc-host/test/fixtures/event-fidelity/claude/post-patch/` (pre-patch fixtures in the parent directory are untouched, so the phase-0 line references above remain valid).

Post-patch observations:

- The completed `command_execution` item (`post-patch/claude-normalized.jsonl` line 20) carries `payload.data.result.fullOutput` with the full 108,894-byte `seq 1 20000` output (`fullOutputSize: 108894`, `fullOutputPath` pointing at the sidecar). The fixture trims the string with a `[...trimmed N bytes...]` marker; `post-patch/claude-normalized-summary.json` records the true `completedDataBytes: 132165`.
- Both turns emitted `reasoning` items: `item.started`/`item.completed` pairs at lines 8/13 and 31/41 with the thinking text in `payload.detail` (270 and 431 bytes), and 12 `reasoning_text` deltas (696 bytes total in the untrimmed stream) correlated to the reasoning `itemId`.
- Failure/cap behavior (unreadable sidecar, >10 MB persisted size) is covered by unit tests in `ClaudeAdapter.test.ts`: the completed item keeps the preview `result.content` plus `fullOutputPath`/`fullOutputSize` and omits `fullOutput`. The 10 MB cap is enforced in bytes against both the reported `persistedOutputSize` and the sidecar's actual on-disk size (`stat` before read, `Buffer.byteLength` after).
- Path traversal: `persistedOutputPath` is trusted as Claude Code's own sidecar metadata (accepted risk, local-only threat model).

## Deviations

The direct adapter harness worked, so I did not use the dev-server NDJSON fallback. Claude's interrupted turn produced `state: failed` with an interruption diagnostic rather than `state: interrupted`; the rollout separately recorded `[Request interrupted by user]`. The Claude harness process lingered after writing `finishedAt`; I interrupted the probe after all fixture files and turn completions were flushed.

MCP tool calls and true Codex `file_change` items were not observed in these cheap sessions. Codex chose command execution for the file-edit prompt.
